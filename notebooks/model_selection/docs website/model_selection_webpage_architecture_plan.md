# Model-Selection Webpage Architecture Plan

## Goal

Build a webpage where a user can either:

1. choose a dataset already generated by the project, such as Levi, SPPCS, or CS, or
2. upload a new dataset,

then click **Submit** and see:

- selected model prediction,
- model-selection summary table,
- learned vs true kernel plots,
- learned environment-force \(f\) plots,
- rollout or trajectory figures,
- repeated-trial summary tables.

The webpage should display model-selection results generated by the existing Python pipeline. It should not duplicate the learning algorithm in JavaScript.

---

## Important design constraint

GitHub Pages is static. It can display HTML, CSS, JavaScript, images, CSV tables, and JSON files, but it cannot run Python.

Therefore:

```text
GitHub Pages = display precomputed results
Backend server = run Python model selection for uploaded datasets
```

The project should be built in two phases.

---

# Phase 1 — Static GitHub Pages for precomputed results

## Purpose

Display already-generated model-selection results for:

```text
Levi
SPPCS
CS
```

This phase does not support uploaded datasets yet. The user selects a system from a dropdown, and the webpage loads saved website-ready artifacts.

## User flow

```text
Open webpage
    ↓
Choose dataset/system from dropdown:
    Levi / SPPCS / CS
    ↓
Click Submit or Load Results
    ↓
JavaScript loads manifest.json
    ↓
Webpage displays:
    selected model
    summary table
    kernel figures
    f figure
    trajectory figure
    repeated-trial summary table
```

## Required exported artifacts

Each system should have a website-ready folder:

```text
docs/assets/model_selection/{system}/
    manifest.json
    selected_model.json
    model_selection_summary.csv

        scores/

```

Example:

```text
docs/assets/model_selection/levi/
    manifest.json
    selected_model.json

    figures/
        kernels/full_model_energy_kernel.png
```

## What `manifest.json` should contain

The webpage should not hard-code every filename. It should read a manifest file.

Example:

```json
{
  "system_name": "levi",
  "display_name": "Levi / Phototaxis",
  "selected_model": {
    "candidate": "second_order_alignment",
    "primary_metric": "E_traj_prediction",
    "primary_value": 0.0123
  },
  "summary_table": "model_selection_summary.csv",
  "figures": {
    "energy_kernel": "figures/kernels/full_model_energy_kernel.png",
    "alignment_kernel": "figures/kernels/full_model_alignment_kernel.png",
    "environment": "figures/environment/selected_f.png",
    "rollout": "figures/rollouts/selected_validation_rollout.png",
    "selection_summary": "figures/scores/selection_summary.png",
    "kernel_norms": "figures/scores/kernel_norms.png"
  },
  "repeated_trials": {
    "selection_frequency": "repeated_trials/selection_frequency.csv",
    "selected_metric_summary": "repeated_trials/selected_metric_summary.csv",
    "candidate_metric_summary": "repeated_trials/candidate_metric_summary.csv"
  }
}
```

## Phase 1 frontend structure

Use a simple static frontend:

```text
docs/
    index.html
    css/
        style.css
    js/
        app.js
    assets/
        model_selection/
            levi/
            sppcs/
            cs/
```

## Phase 1 responsibilities

### Python pipeline

The Python pipeline is responsible for producing artifacts:

```text
run model selection
save selected_model.json
save summary CSV
save figures
save repeated-trial summaries
export to docs/assets/model_selection/{system}/
```

### Website JavaScript

The JavaScript is responsible only for display:

```text
load manifest.json
load selected_model.json
load CSV tables
insert images into page
render tables
```

It does not run fitting, rollout, scoring, or density estimation.

# Phase 2 — Interactive backend for uploaded datasets

## Purpose

Allow a user to upload a dataset and run model selection after clicking Submit.

This requires a backend server because Python must run.

Possible backend choices:

```text
FastAPI
Flask
Hugging Face Spaces
Render
Railway
university server
local server
```

GitHub Pages alone cannot support this.

## Uploaded dataset flow

```text
User uploads .npz dataset
    ↓
Backend validates dataset format
    ↓
Backend saves dataset into artifacts/datasets/user_uploads/{job_id}/
    ↓
Backend runs model-selection pipeline
    ↓
Backend generates figures and summary tables
    ↓
Backend exports website-ready result folder
    ↓
Frontend loads manifest.json for that job
    ↓
Webpage displays results
```

## Required uploaded dataset format

For second-order model selection, require an `.npz` file with:

```text
t
X
V
LHS
U0
metadata
```

Expected shapes:

```text
X.shape   = (M, L, N, D)
V.shape   = (M, L, N, D)
LHS.shape = (M, L, N, D)
t.shape   = (L,)
```

For first-order model selection, require:

```text
t
X
LHS
U0
metadata
```

Expected shapes:

```text
X.shape   = (M, L, N, D)
LHS.shape = (M, L, N, D)
t.shape   = (L,)
```

## Phase 2 backend structure

```text
webapp/
    backend/
        app.py
        jobs.py
        dataset_upload.py
    frontend/
        index.html
        app.js
        style.css
```

## Backend endpoints

```text
POST /run-model-selection
GET  /job-status/{job_id}
GET  /results/{job_id}/manifest.json
```

## Example backend request for existing dataset

```json
{
  "source": "existing",
  "system_name": "levi",
  "profile_name": "levi_velocity_grid",
  "model_selection_mode": "second_order"
}
```

## Example backend request for uploaded dataset

```json
{
  "source": "upload",
  "job_id": "abc123",
  "system_order": 2,
  "model_selection_mode": "second_order"
}
```

# Recommended implementation order

## Phase 1 first

Start with static GitHub Pages. This is the safest first step because all results are already generated by the notebooks.

Phase 1 steps:

```text
1. Standardize website export folders.
2. Create manifest.json for each system.
3. Create index.html.
4. Create app.js to load selected system results.
5. Render selected model card.
6. Render summary table from CSV.
7. Render kernel/f/trajectory figures.
8. Render repeated-trial summary tables.
9. Test locally.
10. Publish with GitHub Pages.
```

## Phase 2 later

After Phase 1 works, add backend support for uploaded datasets.

Phase 2 steps:

```text
1. Build FastAPI backend.
2. Add dataset upload endpoint.
3. Validate uploaded dataset format.
4. Convert upload into internal artifact format.
5. Run model-selection pipeline from backend.
6. Save job-specific website export.
7. Add job polling to frontend.
8. Display uploaded-dataset results.
```

---

# Key rule

The webpage should not regenerate results unless a backend job is explicitly requested.

For Phase 1:

```text
notebooks / Python pipeline → generate artifacts once
website → load and display artifacts
```

For Phase 2:

```text
backend → runs Python model selection
frontend → displays backend-generated artifacts
```
